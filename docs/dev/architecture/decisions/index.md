# 架构决策记录（ADR）

本目录记录本项目的架构与工具选型决策，供人类与 AI 协作时了解「为什么这么做」，避免改动时重拾已淘汰方案。

## 风格

采用 **Nygard 轻量风格**：每篇 ADR 含元数据（状态、日期）与三个段落——背景、决策、后果。模板见 `_template.md`。

## 规则

- **顺序编号、不可变**：文件名 `NNNN-短文标题.md` 递增编号；已采纳的 ADR 绝不改写。
- **状态驱动**：`提议` / `已采纳` / `已废弃` / `已取代（由 NNNN 取代）`。只有 `已采纳` 才算约束。
- **一篇一决策**：只记一个决策，超过两屏应拆分。
- **变更写新篇**：推翻或修订既有 ADR 时，写新的已采纳 ADR，将旧篇标记为 `已取代`，保留演进轨迹。

## 何时写

凡遇到带权衡的“该不该”、“用哪个”——工具选型、目录结构、依赖取舍、接口边界——都写一篇。
